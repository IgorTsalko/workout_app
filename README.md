# Дневник тренировок

Одна HTML-страница без сервера и без зависимостей. Ведёт историю тренировок, показывает план на сегодня и обменивается данными с Claude через копирование промпта тренера и вставку итогового JSON.

## Запуск

Откройте `index.html` в браузере двойным щелчком. Интернет не нужен.

## Цикл работы

1. **План** (вкладка подписана датой и днём недели плана, например «Пт, 16 окт»): план на текущую тренировку, итог прошлой и рекомендация от Claude.
   Над планом — переключатель последних 4 тренировок, включая текущую: карточки с днём недели, датой и отметкой «сделано», от старых слева к текущей справа. У прошлой тренировки вместо «↩ Прошлый раз» под каждым упражнением строка **«✓ Сделано»** из записи в истории, а сверху — итог записи (статус, дата, самочувствие, заметки). Дата на переключателе — день, когда тренировка записана в историю, а если записи ещё нет — дата из плана (`date`).
   План показан как ход тренировки: разминка, упражнения и заминка по порядку, с общей нумерацией (разминка — №1, заминка — последний номер). У каждого пункта есть время «с какой по какую минуту». В упражнении две группы подходов: **разминка** одной строкой («20×15 · 45×6 · 62.5×3») и **рабочие** крупно («3 × 6 · 77.5 кг»), у каждой группы указан отдых между подходами. Под схемой подходов — строка **«↩ Прошлый раз»**: рабочие подходы, веса и RPE этого упражнения из последней выполненной тренировки, где оно было, и короткая заметка к нему (если упражнения в истории нет, строки нет). Она же есть в картинке PNG и в тексте. Внизу карточки — плашка «⏸ Отдых 3 мин» перед следующим упражнением. Общее время приложение считает само: подход ≈ 3 сек на повтор + 10 сек, разминочный подход + 1 мин, отдых между подходами и упражнениями, переход между частями суперсета 15 сек. Время подсвечивается, если план дольше ориентира больше чем на 5 минут; такой план приложение не примет молча (см. «Проверка при загрузке»).
   План можно забрать на телефон: **картинка PNG** (сохранить в галерею), **PDF** через окно печати («Сохранить как PDF»), **текст с чекбоксами ☐** для заметок или мессенджера, а на телефоне ещё и кнопка «Поделиться».
2. **Тренер → Шаг 1**: после тренировки описать своими словами, как всё прошло, без заданного формата: по номерам упражнений, веса, повторы, ощущения, самочувствие, сон, вес тела, пожелания, вопросы к тренеру, а также пропуск или болезнь. Номера упражнений плана можно раскрыть под полем. Затем скопировать **промпт тренера** или скачать его как `.md` и отправить в чат Claude. Описание попадает в промпт как есть. Подробно: [docs/use-case-workout-report.md](docs/use-case-workout-report.md).
3. **Тренер → Шаг 2, обсуждение**: тренер не выдаёт JSON сразу. Первый ответ — разбор тренировки (2–5 предложений), ответы на вопросы из описания, разбор пожеланий, каркас (тип тренировки, бюджет времени, таблица баланса мышечных групп), план следующей тренировки с объяснением каждого упражнения, строка проверки (время, суперсеты, новые упражнения, чем жертвует) и вопросы, если без них план не собрать. Дальше обычный диалог: уточнить, поспорить, попросить замену; в ответах тренер перечисляет только изменения, а не весь план. Когда со всем согласны, написать «финал».
4. **Тренер → Шаг 3**: вставить финальный ответ тренера целиком. Приложение найдёт в нём блок ```json, проверит план, запишет разобранную тренировку в историю (`completed_workout`) и покажет новый план на вкладке плана. Что Claude додумал, видно в записи в «Истории»; ошибку можно поправить кнопкой «Редактировать».
5. **История / Прогресс**: список записей с редактированием, календарь посещаемости за 8 недель, графики по каждому упражнению.

### Тренер в отдельном проекте Claude

Второй способ, без копирования промпта и вставки JSON. Приложение кладёт промпт тренера в репозиторий автобэкапа (`coach-prompt.md`), тренер в отдельном проекте Claude читает его, обсуждает с вами тренировку и после «финал» сам коммитит ответ в `coach-answer.json`. При открытии или обновлении страницы приложение загружает этот ответ так же, как на шаге 3, и заодно забирает данные, если их поменяли с другого устройства. Как настроить и текст инструкций для проекта: [docs/coach-project.md](docs/coach-project.md).

## Что попадает в промпт тренера

- Профиль «Обо мне»: возраст (считается от даты рождения), рост, вес (последний записанный в тренировках), цель, опыт, расписание, ориентир по длительности, лимит суперсетов, отдых, оборудование, ограничения, «Не предлагать», «Что нравится» и постоянные рекомендации тренера. Исходные значения заданы в `index.html` (константа `PROFILE`).
- Последний выданный план.
- **Последние N записей подробно** (по умолчанию 6, примерно 3 недели при 2 тренировках в неделю), включая пропуски и болезни.
- **Сводка по всей истории**: посещаемость по неделям и прогресс каждого упражнения (первый результат → лучший → последний).
- **Мои пожелания**: из описания тренировки на вкладке «Тренер» (Claude сам находит в нём пожелания и то, на чём вы настаиваете: «настаиваю», «обязательно», «важно», отдельно по каждому пожеланию) и из записей после последнего плана, а также все действующие требования.
- **Порядок работы**: этап 1 — разбор и предложение без JSON, этап 2 — обсуждение (только изменения, каждая правка — пересборка с равным сокращением по времени), этап 3 — JSON только по явной команде («финал», «давай JSON»).
- **Каким быть тренеру**: менять решение только при новом аргументе или факте, без «вы абсолютно правы» и общих советов; если ошибся — назвать, в чём именно; оставленное по настоянию так и называть, без подогнанного обоснования; оценку называть оценкой; вес писать «30 кг × 10 раз»; при расхождении отчёта с назначением упражнения сначала спрашивать цель; вопрос про тренажёр задавать с описанием; если вы исправили план, назвать ошибку и правило, которое к ней привело, и обновить свои рекомендации, чтобы она не повторилась.
- **Как подбирать план, от общего к частному**: 1) неделя и тип тренировки (при двух тренировках в неделю обе на всё тело, сплит из истории не наследуется); 2) бюджет мышечных групп по окну «прошлая тренировка + этот план» с неизменными правилами подсчёта; 3) бюджет времени; 4) каркас из слотов движений, упражнения на одну группу — подряд или в одном суперсете, а не в разных местах плана; 5) упражнения в слоты: сначала то, что уже делаете, потом «Что нравится», новых не больше двух, ничего из «Не предлагать», без дублей (упражнение, которое вы делаете в разминке, выносится отдельным пунктом №2, а не повторяется в основной части); 6) подходы, вес и отдых по истории, всё различие подходов — в `sets_detail`; 7) проверка перед каждым показом плана: время не больше ориентира + 5 мин, суперсетов не больше лимита, каждая группа в норме или названа жертва.
- **Правила принятия решений**: безопасность → эффективность для цели → пожелания. Спорное пожелание Claude не применяет, а объясняет риск и предлагает альтернативу. Пожелание, на котором вы настаиваете, применяет, но с предупреждением и советом, как снизить риск.
- Требование к формату финального ответа: строгая JSON-схема. Кроме плана, в ответе есть `warnings` (риски), `answers` (ответы на вопросы из описания) и `wishes_review` (что сделано с каждым пожеланием: принято / изменено / не принято / принято по настоянию). На вкладке плана они показаны отдельными блоками.

Требования, на которых вы настояли, действуют, пока их не отменить: «Данные → Мои требования».

## Тренер обновляет «Обо мне»

Claude ведёт данные на вкладке «Данные» сам. Если по итогам тренировки нужно что-то поправить (появилась боль, снято ограничение, подобран отдых, есть постоянная рекомендация), он добавляет в ответ `profile_update` только с изменившимися полями:

```json
"profile_update": {
  "rest": "Базовые упражнения: 2.5–3 мин; изоляция: 60–90 сек.",
  "recommendations": "Записывай вес тела раз в неделю.",
  "session_minutes": 75,
  "reason": "Подобрал отдых под цель"
}
```

Поля: `goal`, `experience`, `schedule`, `duration`, `rest`, `equipment`, `limitations`, `avoid` («Не предлагать»: от чего вы отказались), `likes` («Что нравится»), `recommendations` (полный новый текст поля), а также числа `session_minutes` (ориентир по времени, по нему считается длительность плана) и `max_supersets` (лимит суперсетов в плане). Тренер меняет только поля, по которым в чате появился новый факт. Изменения применяются при загрузке ответа, показываются на вкладке плана блоком «Тренер обновил «Обо мне»» и попадают в историю изменений на вкладке «Данные». Любое поле можно поправить вручную или вернуть к исходному. Ответ может содержать только `profile_update`, без плана.

Почему не вся история: старые подходы почти ничего не добавляют к решению о следующей тренировке, но раздувают prompt. Тренд за весь период остаётся в компактной сводке. N меняется на вкладке «Тренер».

## Проверка при загрузке

Перед загрузкой плана приложение проверяет:

- одно и то же упражнение дважды: в основной части, в суперсете и в разминке или заминке (название упражнения упомянуто в их описании, например «гиперэкстензия» в разминке и «Гиперэкстензия» в суперсете);
- упражнения из «Не предлагать» (пункты через запятую или точку с запятой);
- суперсетов больше лимита из «Обо мне»;
- время по расчёту приложения больше ориентира + 5 минут;
- у части суперсета в `sets_detail` рабочих подходов не столько, сколько кругов.

Если что-то нашло, показывает список: «Отмена» копирует замечания, чтобы вернуть их тренеру в чат, «ОК» загружает план как есть, а замечания попадают в блок «⚠ Важно». Номера упражнений из `completed_workout`, которых нет в плане, не теряются молча: они попадают в «Как Claude понял описание — проверьте».

## Откат загрузки

Перед каждой загрузкой ответа тренера приложение сохраняет снимок всех данных и текст описания. На вкладке плана, в «Истории» и на шаге 3 вкладки «Тренер» появляется плашка «Загружен ответ тренера… ↶ Откатить загрузку». Откат удаляет запись о тренировке, новый план и правки «Обо мне» из этого ответа и возвращает описание в поле, чтобы можно было поправить его или вернуться в чат с тренером. Хранится только последняя загрузка; загрузка стартовых данных, восстановление из бэкапа и сброс снимок удаляют.

## Формат ответа Claude

Если в промпте было описание тренировки, в ответе есть ещё `completed_workout`: запись о тренировке, где упражнения плана указаны по номеру (`"tag": "2"`, `"5А"`), а «как в плане» — `"as_planned": true`. Формат описан в [docs/use-case-workout-report.md](docs/use-case-workout-report.md).

```json
{
  "summary": "Итог прошедшей тренировки",
  "recommendation": "Короткая рекомендация",
  "next_workout": {
    "date": "2026-10-05",
    "title": "Вторник — грудь + ноги",
    "focus": "Грудь, квадрицепс",
    "duration_min": 65,
    "rest_between_exercises_sec": 180,
    "warmup": "…",
    "exercises": [
      { "name": "Жим ногами в гак-машине", "sets": 3, "reps": 8, "unit": "reps",
        "weight": 57.5, "rest_sec": 150, "rpe": 90, "change": "+2.5 кг", "notes": "…" }
    ],
    "cooldown": "…",
    "notes": "…"
  }
}
```

`rpe` — проценты (50–100). `weight: null` — вес подобрать на месте. `sets_detail` — необязательный список подходов, когда веса различаются или есть разминочные (`"warmup": true`).

Суперсет — один пункт плана: `{"type": "superset", "name": "плечи + трапеция", "rounds": 3, "rest_sec": 90, "parts": [ … ]}`. В `parts` лежат обычные упражнения, их делают подряд без отдыха. У части тоже может быть `sets_detail`: разминочные подходы делаются до первого круга, а рабочих ровно столько, сколько кругов (например, первый круг гиперэкстензии с 5 кг, остальные с 10 кг). Время приложение считает по каждому кругу. В приложении суперсет выглядит как одна карточка с частями А и Б, а при записи тренировки части идут отдельно с метками «5А» и «5Б», чтобы по каждому упражнению строился свой график.

## Хранение данных

Данные лежат в `localStorage` браузера: это самый простой вариант, работает с `file://` и ничего не требует ставить. Ограничения:

- данные привязаны к конкретному браузеру на конкретном устройстве;
- пропадут, если очистить данные сайтов.

Поэтому в разделе **Профиль и данные** есть **бэкап в JSON-файл** и восстановление из него. Через этот же файл можно перенести данные на другое устройство.

### Автобэкап в GitHub

На вкладке «Данные» можно один раз подключить свой репозиторий, и дальше приложение само коммитит снимок всех данных в файл `workout-backup.json` после каждого сохранения: записанная тренировка, загруженный ответ тренера, правка, откат. Несколько сохранений подряд уходят одним коммитом, история версий — это история файла в git.

Подключение (один раз):

1. Создать приватный репозиторий, например `workout-backup`.
2. Создать fine-grained токен (GitHub → Settings → Developer settings → Fine-grained tokens): доступ только к этому репозиторию, право **Contents: Read and write**.
3. «Данные → Автобэкап в GitHub»: вписать `владелец/имя` репозитория и токен, нажать «Подключить».

Токен хранится только в `localStorage` этого браузера и в бэкап не попадает. Если при подключении в репозитории уже есть бэкап (например, с другого устройства), приложение предложит взять данные из него. Если сети нет, бэкап отправится при следующем сохранении или открытии страницы. «Восстановить из GitHub» заменяет данные браузера последней версией из репозитория. При открытии страницы приложение само забирает данные, если их поменяли с другого устройства, поэтому телефон и компьютер не затирают друг друга.

## Стартовые данные

При первом открытии загружаются стартовые данные:

- текущая программа в виде двух записей: «Вторник — грудь» (29.09) и «Пятница — спина» (02.10);
- план первой тренировки: «Вторник — грудь + ноги» на 06.10.

Если в браузере уже есть другие данные (например, демо из прошлой версии), загрузите стартовые вручную: «Данные → Загрузить стартовые данные».
