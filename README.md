# Дневник тренировок

Одна HTML-страница без сервера и без зависимостей. Ведёт историю тренировок, показывает план на сегодня и обменивается данными с Claude через копирование prompt и вставку ответа.

## Запуск

Откройте `index.html` в браузере двойным щелчком. Интернет не нужен.

## Цикл работы

1. **Сегодня**: план на текущую тренировку, итог прошлой и рекомендация от Claude.
   План показан как ход тренировки: разминка, упражнения и заминка по порядку. У каждого пункта есть время «с какой по какую минуту». В упражнении две группы подходов: **разминка** одной строкой («20×15 · 45×6 · 62.5×3») и **рабочие** крупно («3 × 6 · 77.5 кг»), у каждой группы указан отдых между подходами. Внизу карточки — плашка «⏸ Отдых 3 мин» перед следующим упражнением. Общее время приложение считает само: подход ≈ 3 сек на повтор + 10 сек, разминочный подход + 1 мин, отдых между подходами и упражнениями, переход между частями суперсета 15 сек. Если план не укладывается в лимит, время подсвечивается.
   План можно забрать на телефон: **картинка PNG** (сохранить в галерею), **PDF** через окно печати («Сохранить как PDF»), **текст с чекбоксами ☐** для заметок или мессенджера, а на телефоне ещё и кнопка «Поделиться».
2. **Claude ⇄ → Шаг 1**: после тренировки описать своими словами, как всё прошло, без заданного формата: по номерам упражнений, веса, повторы, ощущения, самочувствие, сон, вес тела, пожелания, а также пропуск или болезнь. Номера упражнений плана можно раскрыть под полем. Затем скопировать prompt или скачать его как `.md` и отправить в чат Claude. Описание попадает в prompt как есть. Подробно: [docs/use-case-workout-report.md](docs/use-case-workout-report.md).
3. **Claude ⇄ → Шаг 2**: вставить ответ Claude целиком. Приложение найдёт в нём блок ```json, запишет разобранную тренировку в историю (`completed_workout`) и покажет новый план на вкладке «Сегодня». Что Claude додумал, видно в записи в «Истории»; ошибку можно поправить кнопкой «Редактировать».
4. **История / Прогресс**: список записей с редактированием, календарь посещаемости за 8 недель, графики по каждому упражнению.

## Что попадает в prompt

- Профиль: возраст, рост, вес (последний записанный), цель, опыт, расписание, лимит по времени, ограничения. Профиль один и задан в `index.html` (константа `PROFILE`).
- Последний выданный план.
- **Последние N записей подробно** (по умолчанию 6, примерно 3 недели при 2 тренировках в неделю), включая пропуски и болезни.
- **Сводка по всей истории**: посещаемость по неделям и прогресс каждого упражнения (первый результат → лучший → последний).
- **Мои пожелания**: из поля на вкладке Claude и из записей после последнего плана, а также все действующие требования с отметкой «Настаиваю».
- **Правила принятия решений**: безопасность → эффективность для цели → пожелания. Спорное пожелание Claude не применяет, а объясняет риск и предлагает альтернативу. Пожелание с отметкой «Настаиваю» применяет, но с предупреждением и советом, как снизить риск.
- Требование к формату ответа: строгая JSON-схема. Кроме плана, в ответе есть `warnings` (риски) и `wishes_review` (что сделано с каждым пожеланием: принято / изменено / не принято / принято по настоянию). На вкладке «Сегодня» они показаны отдельными блоками.

Требования с отметкой «Настаиваю» действуют, пока их не отменить: «Данные → Мои требования».

Почему не вся история: старые подходы почти ничего не добавляют к решению о следующей тренировке, но раздувают prompt. Тренд за весь период остаётся в компактной сводке. N меняется на вкладке Claude.

## Формат ответа Claude

Если в prompt было описание тренировки, в ответе есть ещё `completed_workout`: запись о тренировке, где упражнения плана указаны по номеру (`"tag": "2"`, `"5А"`), а «как в плане» — `"as_planned": true`. Формат описан в [docs/use-case-workout-report.md](docs/use-case-workout-report.md).

```json
{
  "summary": "Итог прошедшей тренировки",
  "recommendation": "Короткая рекомендация",
  "next_workout": {
    "date": "2026-10-05",
    "title": "Вторник — грудь + ноги",
    "focus": "Грудь, квадрицепс",
    "duration_min": 65,
    "rest_between_exercises_sec": 180,
    "warmup": "…",
    "exercises": [
      { "name": "Жим ногами в гак-машине", "sets": 3, "reps": 8, "unit": "reps",
        "weight": 57.5, "rest_sec": 150, "rpe": 90, "change": "+2.5 кг", "notes": "…" }
    ],
    "cooldown": "…",
    "notes": "…"
  }
}
```

`rpe` — проценты (50–100). `weight: null` — вес подобрать на месте. `sets_detail` — необязательный список подходов, когда веса различаются или есть разминочные (`"warmup": true`).

Суперсет — один пункт плана: `{"type": "superset", "name": "плечи + трапеция", "rounds": 3, "rest_sec": 90, "parts": [ … ]}`. В `parts` лежат обычные упражнения, их делают подряд без отдыха. В приложении суперсет выглядит как одна карточка с частями А и Б, а при записи тренировки части идут отдельно с метками «5А» и «5Б», чтобы по каждому упражнению строился свой график.

## Хранение данных

Данные лежат в `localStorage` браузера: это самый простой вариант, работает с `file://` и ничего не требует ставить. Ограничения:

- данные привязаны к конкретному браузеру на конкретном устройстве;
- пропадут, если очистить данные сайтов.

Поэтому в разделе **Профиль и данные** есть **бэкап в JSON-файл** и восстановление из него. Через этот же файл можно перенести данные на другое устройство.

## Стартовые данные

При первом открытии загружаются стартовые данные:

- текущая программа в виде двух записей: «Вторник — грудь» (29.09) и «Пятница — спина» (02.10);
- план первой тренировки: «Вторник — грудь + ноги» на 06.10.

Если в браузере уже есть другие данные (например, демо из прошлой версии), загрузите стартовые вручную: «Данные → Загрузить стартовые данные».
