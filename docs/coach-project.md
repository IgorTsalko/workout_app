# Тренер в отдельном проекте Claude

Единственный способ описать тренировку и получить план: копирования промпта и вставки JSON в приложении больше нет.

## Как это устроено

В репозитории автобэкапа (например, `IgorTsalko/workout-backup`) лежат:

| Файл | Кто пишет | Кто читает | Что в нём |
| --- | --- | --- | --- |
| `workout-backup.json` | приложение | приложение, тренер (только чтение) | все данные |
| `coach-prompt.md` | приложение | тренер, в начале чата | вход: порядок шести стадий, какой файл читать на какой стадии, общие правила |
| `coach/data.md` | приложение | тренер | «Обо мне», последний план с номерами, две последние записи, сводка, «Прогресс по упражнениям» |
| `coach/stage-1-report.md` … `coach/stage-6-plan.md` | приложение | тренер, каждый перед своей стадией | правила одной стадии и форма её вывода |
| `coach/final.md` | приложение | тренер, по команде «финал» | правила финала и формат JSON |
| `coach/dossier.md` | тренер | тренер | досье: вывод по всей истории, обновляется после каждой тренировки |
| `coach-answer.json` | тренер | приложение | финальный JSON тренера по формату из `coach/final.md` |

1. После каждого сохранения приложение коммитит `workout-backup.json` и те файлы задания, чей текст изменился (обычно только `coach/data.md`). В задании сказано, что текст о тренировке придёт в чат, тренер проходит шесть стадий, а в финале сам записывает JSON в `coach-answer.json` и досье в `coach/dossier.md`.
2. В проекте Claude вы пишете, как прошла тренировка. Тренер отвечает по стадиям: отчёт, разбор, досье, диагноз, задача, план. Вы обсуждаете план и пишете «финал». Тренер коммитит `coach-answer.json` и `coach/dossier.md` прямо в основную ветку.
3. При открытии, обновлении страницы или возврате на вкладку (не чаще раза в минуту) приложение:
   - забирает `workout-backup.json`, если его поменяли с другого устройства (если и здесь есть неотправленные изменения, спрашивает, чьи оставить);
   - загружает `coach-answer.json`, если он новый: записывает тренировку в историю, применяет `profile_update`, показывает план на вкладке плана. Ошибки проверки плана не блокируют загрузку, а попадают в «⚠ Важно». Загрузку можно откатить кнопкой «↶ Откатить загрузку», повторно этот ответ не загрузится.
   - Какой ответ уже загружен, приложение помнит в данных (`coachInbox`), поэтому на другом устройстве он не загрузится второй раз.
4. Если после финала тренер исправляет план, он перезаписывает оба файла, а в JSON ставит поле `"correction": true`. Приложение убирает всё, что внёс прошлый ответ (запись, план, правки «Обо мне»), и загружает исправленный. Если по прошлому плану уже записана тренировка, исправление ложится поверх, и приложение просит проверить «Историю».

Кнопки «Тренер → Проверить ответ тренера» и «Данные → Автобэкап в GitHub → Проверить GitHub» делают то же, что открытие страницы.

## Что нужно один раз

1. Автобэкап в GitHub подключён («Данные → Автобэкап в GitHub»), токену нужно право **Contents: Read and write**.
2. Новый проект Claude с доступом к репозиторию бэкапа на запись (репозиторий подключён к проекту).
3. В инструкции проекта вставить текст ниже.

## Инструкции для проекта Claude

```text
Ты — мой тренер по силовым тренировкам. Все данные лежат в GitHub-репозитории IgorTsalko/workout-backup, ветка main. Его ведёт моё приложение-дневник.

Файлы в репозитории:
- coach-prompt.md — вход в твоё задание: кто ты, шесть стадий первого ответа, какой файл читать на какой стадии, общие правила. Его пишет приложение.
- coach/data.md — мои данные: «Обо мне», последний план с номерами упражнений, последние записи, сводка и «Прогресс по упражнениям». Пишет приложение, файл всегда актуален.
- coach/stage-1-report.md … coach/stage-6-plan.md — правила каждой стадии. Пишет приложение.
- coach/final.md — правила финала и формат финального JSON. Пишет приложение.
- coach/dossier.md — досье: твой вывод по всей истории. Пишешь его ты, в финале.
- coach-answer.json — сюда ты записываешь финальный JSON. Приложение подхватит его, когда я открою или обновлю страницу.
- workout-backup.json — все данные приложения. Только читать.

В начале каждого чата:
1. Возьми свежую версию main (git pull или прочитай файлы из GitHub) и прочитай целиком coach-prompt.md, coach/data.md и coach/dossier.md. coach-prompt.md — твои инструкции, следуй им во всём.
2. Моё сообщение — это описание прошедшей тренировки, свободным текстом, по номерам упражнений из последнего плана в coach/data.md. С него начинается стадия 1.
3. Иди по стадиям по порядку. Файл стадии читай прямо перед этой стадией, не все сразу. Каждую стадию заканчивай её выводом и только потом переходи к следующей.
4. Сегодняшнюю дату узнай сам (команда date).

Финал, когда я скажу «финал» или «давай JSON»:
1. Ещё раз скачай main (вдруг приложение обновило данные), прочитай coach/final.md и собери JSON строго по формату из него.
2. Запиши JSON в coach-answer.json в корне репозитория: только JSON, без текста вокруг, перезаписав файл целиком. Запиши обновлённое досье в coach/dossier.md, тоже целиком.
3. Закоммить оба файла одним коммитом прямо в main и запушь: без веток и без pull request. Сообщение коммита: «Ответ тренера: <название плана> на <дата>». Если git push в main не проходит, запиши файлы через GitHub (create_or_update_file, branch main): сначала досье, потом coach-answer.json.
4. Проверь, что коммит есть в main на GitHub, и напиши мне одной строкой, что записал.
5. Если после финала я попрошу исправить план, исправь, снова перезапиши coach-answer.json и coach/dossier.md целиком и добавь в JSON поле "correction": true. Тогда приложение заменит прошлый ответ из этого чата, а не добавит вторую тренировку. В новом чате это поле не ставь.

Нельзя:
- менять какие-либо файлы, кроме coach-answer.json и coach/dossier.md;
- создавать ветки и pull request;
- писать в репозиторий до моей команды «финал».
```

## Досье

`coach/dossier.md` — вывод тренера по истории: общая картина, группы мышц, карточка на каждое упражнение (путь, где сейчас, что пробовали, на что реагирует, следующий шаг), стратегия, прогноз на выданный план, открытые гипотезы. Формат и правила обновления лежат в `coach/stage-3-dossier.md`.

- Приложение файл не читает и не меняет. «Откатить загрузку» в приложении досье не откатывает: в следующем чате тренер сверит шапку «Учтено по» со списком записей из `coach/data.md` и поправит досье сам.
- Если файла нет, тренер соберёт его с нуля из `workout-backup.json` в первом же чате. То же по просьбе «пересобери досье».
- Файл можно править руками: тренер прочитает его как есть.
