# Use case: записать тренировку одним сообщением через Claude

## Задача

Не заполнять форму по каждому подходу. После тренировки описать её своими словами, без заданного формата, и получить готовую запись в истории.

Приложение не обращается к AI напрямую. Обмен идёт через копирование: приложение выгружает prompt, Claude отвечает, ответ вставляется обратно.

## Порядок действий

1. **Сегодня.** Тренируешься по плану. У каждого упражнения есть номер: 1, 2, 3…, части суперсета — 4А, 4Б. Те же номера на картинке PNG и в тексте с чекбоксами.
2. **Описать.** После тренировки пишешь на вкладке «Описать», как всё прошло. Формат любой: номера, названия, цифры, ощущения, самочувствие, сон, вес тела, пожелания. Если тренировку пропустил или заболел, пишешь и это. Под полем показаны номера упражнений текущего плана, для подсказки. Текст сохраняется сам.
3. **Скопировать prompt.** Кнопка «Скопировать prompt для Claude» на той же вкладке (или «Claude ⇄ → Шаг 1»). В prompt попадают план с номерами, твой текст как есть и правила разбора.
4. **Claude.** Вставляешь prompt в чат. Claude возвращает один блок ```json, в котором:
   - `completed_workout` — разобранная тренировка;
   - `summary`, `recommendation`, `warnings`, `wishes_review`, `next_workout` — итог и новый план, как раньше.
5. **Загрузить ответ.** «Claude ⇄ → Шаг 2»: вставляешь ответ целиком и жмёшь «Загрузить ответ». Приложение записывает тренировку в историю и загружает новый план. Поле «Описать» очищается.
6. **Проверить.** Если Claude что-то додумал (например, про упражнение ничего не было сказано и он посчитал его по плану), приложение открывает «Историю», и в записи есть блок «Как Claude понял описание — проверьте». Ошибку можно поправить кнопкой «Редактировать».

Ручная форма осталась только для правки уже сохранённых записей.

## Формат `completed_workout`

```json
{
  "date": "2026-10-07",
  "status": "done",
  "exercises": [
    { "tag": "1", "as_planned": true, "rpe": 85 },
    { "tag": "2", "rpe": 95, "notes": "последний подход тяжело",
      "sets": [ { "weight": 80, "reps": 6 }, { "weight": 80, "reps": 6 }, { "weight": 80, "reps": 5 } ] },
    { "tag": "4А", "skipped": true, "notes": "не успел" },
    { "tag": null, "name": "Шраги с гантелями стоя", "sets": [ { "weight": 30, "reps": 15 } ] }
  ],
  "wellbeing": 4, "effort": 85, "duration": 65, "sleep": 7, "bodyweight": 76.4,
  "notes": "", "extras": "", "reason": "",
  "wishes": "больше трапеции", "insist": true,
  "assumptions": ["3: в тексте не упомянуто, считаю по плану"]
}
```

| Поле | Смысл |
|---|---|
| `tag` | Номер из плана. Название и плановые цифры приложение берёт из плана по номеру. Номер целого суперсета («4») разворачивается во все его части. Латинские буквы (`4a`, `4B`) тоже понимаются. |
| `as_planned` | Сделано как в плане: подходы копирует приложение, Claude их не переписывает. |
| `sets` | Фактические подходы, если что-то отличалось от плана. |
| `skipped` | Упражнение не делал: в истории подходы плана помечаются как невыполненные. |
| `tag: null` + `name` | Упражнение не из плана. |
| `status` | `done`, `skipped` (пропуск) или `sick` (болезнь); для двух последних — `reason`, без упражнений. |
| `assumptions` | Что Claude додумал или понял двояко. Показывается в «Истории». |

Чего нет в тексте, то `null`. Пожелания из текста попадают в запись (`wishes`, `insist`) и разбираются в `wishes_review` того же ответа.

## Варианты

- **Ответ без `completed_workout`** (описания не было): загружается только план, как раньше.
- **Ответ только с `completed_workout`** (без `next_workout`): тренировка записывается, план не меняется.
- **Тот же ответ вставлен повторно**: приложение спросит, загружать ли его ещё раз.
