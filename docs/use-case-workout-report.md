# Use case: записать тренировку одним сообщением через Claude

## Задача

Не заполнять форму по каждому подходу. После тренировки описать её своими словами, без заданного формата, и получить готовую запись в истории.

Приложение не обращается к AI напрямую. Обмен идёт через репозиторий автобэкапа: приложение кладёт туда промпт тренера (`coach-prompt.md`), тренер в проекте Claude читает его и после «финал» коммитит ответ в `coach-answer.json` (см. [coach-project.md](coach-project.md)).

## Порядок действий

1. **План** (вкладка с датой тренировки). Тренируешься по плану. У каждого пункта есть номер: разминка — 1, дальше упражнения 2, 3…, части суперсета — 4А, 4Б, заминка — последний номер. Те же номера на картинке PNG и на вкладке «Тренер».
2. **Чат проекта «Тренер» в Claude.** После тренировки пишешь, как всё прошло. Формат любой: номера, названия, цифры, ощущения, самочувствие, сон, вес тела, пожелания и вопросы к тренеру прямо по ходу текста («4А — правильно ли я делаю, если тянет поясницу?»). Если тренировку пропустил или заболел, пишешь и это.
3. **Обсуждение.** Первый ответ — без JSON: разбор тренировки, ответы на каждый вопрос из текста, разбор пожеланий, план следующей тренировки с объяснением каждого упражнения и баланс мышечных групп за неделю. Дальше уточняешь и споришь сколько нужно. Когда согласен, пишешь «финал» — тренер записывает в `coach-answer.json` JSON, в котором:
   - `completed_workout` — разобранная тренировка с учётом уточнений из обсуждения;
   - `answers` — вопросы из текста и итоговые ответы;
   - `summary`, `brief`, `recommendation`, `warnings`, `wishes_review`, `next_workout` — итог, цель следующей тренировки и новый план.
4. **Открыть приложение.** Оно загружает ответ, проверяет план (одно упражнение дважды, в том числе в разминке; «Не предлагать»; лимит суперсетов; время), записывает тренировку в историю и показывает новый план. Ответы на вопросы — в свёрнутой строке «❓ Ответы тренера» на вкладке плана.
5. **Проверить.** Если Claude что-то додумал (например, про упражнение ничего не было сказано и он посчитал его по плану), приложение открывает «Историю», и в записи есть блок «Как Claude понял описание — проверьте». Ошибку можно поправить кнопкой «Редактировать».

Ручная форма осталась только для правки уже сохранённых записей.

## Формат `completed_workout`

```json
{
  "date": "2026-10-07",
  "status": "done",
  "exercises": [
    { "tag": "2", "as_planned": true, "rpe": 85 },
    { "tag": "3", "rpe": 95, "notes": "последний подход тяжело",
      "sets": [ { "weight": 80, "reps": 6 }, { "weight": 80, "reps": 6 }, { "weight": 80, "reps": 5 } ] },
    { "tag": "4А", "skipped": true, "notes": "не успел" },
    { "tag": null, "name": "Шраги с гантелями стоя", "sets": [ { "weight": 30, "reps": 15 } ] }
  ],
  "wellbeing": 4, "effort": 85, "duration": 65, "sleep": 7, "bodyweight": 76.4,
  "notes": "", "extras": "", "reason": "",
  "wishes": [ { "text": "больше трапеции", "insist": true }, { "text": "без суперсетов на ноги", "insist": false } ],
  "assumptions": ["5: в тексте не упомянуто, считаю по плану"]
}
```

| Поле | Смысл |
|---|---|
| `tag` | Номер из плана. Название и плановые цифры приложение берёт из плана по номеру. Разминка и заминка в `exercises` не попадают: подходов у них нет, замечания о них идут в `notes`. Номер целого суперсета («4») разворачивается во все его части. Латинские буквы (`4a`, `4B`) тоже понимаются. |
| `as_planned` | Сделано как в плане: подходы копирует приложение, Claude их не переписывает. |
| `sets` | Фактические подходы, если что-то отличалось от плана. |
| `skipped` | Упражнение не делал: в истории подходы плана помечаются как невыполненные. |
| `tag: null` + `name` | Упражнение не из плана. |
| `status` | `done`, `skipped` (пропуск) или `sick` (болезнь); для двух последних — `reason`, без упражнений. |
| `assumptions` | Что Claude додумал или понял двояко. Показывается в «Истории». |

Чего нет в тексте, то `null`. `bodyweight` — только утренний вес натощак; вес после тренировки идёт в `notes`, иначе исказит динамику. Пожелания попадают в запись списком `wishes`, у каждого свой `insist`, и разбираются в `wishes_review` того же ответа. В `wishes` идут только пожелания из текста; договорённости из обсуждения — в план и `wishes_review`, постоянные отказы — в «Не предлагать». На вкладке «Данные → Мои требования» каждое пожелание с «настаиваю» отменяется отдельно. Старый формат (`wishes` строкой и общий `insist`) тоже понимается.

## Варианты

- **Ответ без `completed_workout`** (описания не было): загружается только план, как раньше.
- **Ответ только с `completed_workout`** (без `next_workout`): тренировка записывается, план не меняется.
- **Тот же ответ вставлен повторно**: приложение спросит, загружать ли его ещё раз.
